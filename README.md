# SR-Update
My 5th year UNSW engineering undergraduate thesis project. A fault-tolerant firmware update system for resource-constrained microcontrollers over CAN/CAN-FD.

## Design
This project is intended to support all of Sunswift Racing 8's electronic control units (ECUs) as a flash bootloader. It's purpose is to support the transfer of firmware binaries over the CAN/CAN-FD, ISO-TP and UDS protocols as well as enforce authenticity and integrity checks. It also features fault-tolerance inspired by MCUBoot which includes dual-slot flash layout for safe rollback.

### Features
1. ISO-TP over CAN/CAN-FD and UDS spec compatability including security_control implementation which requires an ED25519 private key to prove validity of the client. This includes using true RNG hardware (if supported) to generate a tester seed. 
2. Firmware integrity and authenticity checking via SHA512 hashes and ED25519 digital signatures (separate to the security_control one for extra security)
3. Dual-slot flash layout which enables safe rollback of new firmware
4. ECU Node ID baked into bootloader to confirm the right firmware is flashed 
5. Heartbeat mechanisms to detect against CAN/CAN-FD setting changes
6. Core boot logic decoupled from MCU specific to allow easy porting (see below) and multi-target support
7. Pretty small, some 22KB flash size max (if compiled using Release preset and link-time optimisation) for the entire bootloader including crypto
8. A python script to package and sign application firmware binaries (not bootlaoder binaries) for flashing


## Repo Layout

```
SR-Update
├── boot_core/                  MCU-agnostic bootloader logic
│   ├── Inc/
│   │   ├── mcu_interface/      Interface each MCU port must implement
│   │   ├── common_config/      Bootloader, ISO-TP and UDS settings
│   │   ├── uds/
│   │   └── isotp/
│   └── Src/                    boot_core sources
│
├── app_sdk/                    Code the application links in to handshake after an update
│
├── mcu/                        Directory containing MCU ports
│   └── stm32g431cb/            stm32g431cb port
│       ├── Core/Src/drivers/   Implementation of boot_core/Inc/mcu_interface/*.h for this MCU
│       ├── Core/Inc/config/    MCU-specific config (flash geometry/layout etc.)
│       ├── cmake/              Toolchain file in here
│       └── CMakeLists.txt      This MCU's own sources/include dirs only (see Porting Instructions)
│
├── ecus/                       One .cmake file per ECU
│   └── <name>.cmake            Which MCU it uses + its ECU_ID (CAN IDs are derived from it)
│
└── host_scripts/               Python tools: fmt_tool (image signing), ota_client (flashing), ecu_tests
```

## Build Instructions

Requires the `arm-none-eabi-gcc` toolchain and Ninja on `PATH`.

Configure and build a specific ECU with CMake presets:

```sh
cmake --preset Debug -DECU=example_ecu
cmake --build --preset Debug # or Release
```

`-DECU=<name>` is required in the CMAKE configuration step and must match a file in `ecus/` (e.g for `ecus/example_ecu.cmake` do `-DECU=example_ecu`). The resulting binary is named `<ecu>_<mcu>_bl`, e.g `example_ecu_stm32g431cb_bl.elf`.

The ECU cmake file defines the target MCU and ECU ID. ISO-TP Tx/Rx CAN IDs are derived from `ECU_ID`
(see `boot_core/Inc/common_config/isotp_config.h`).

```cmake
# ecus/example_ecu.cmake
set(ECU_MCU stm32g431cb)

set(ECU_COMPILE_DEFS
    ECU_ID=0x001
)
```

Add a new ECU by adding a new `ecus/<name>.cmake` file in this shape.

## Porting Instructions
The easiest way is to add a new CubeMX project under `mcu/`. Make sure you tick "generate without main function". The hardware you need to enable:
1. FDCAN with 500kBaud (for now) with interrupts enabled
2. IWDG with prescaler 32, down counter 2000 (assuming your LSI is 32kHz, the default on most boards)
3. RTC enabled, default settings
4. RNG enabled if available.

To add support for a new MCU, create `mcu/<name>/` and provide:

1. **Toolchain file** at `mcu/<name>/cmake/gcc-arm-none-eabi.cmake`. This path is fixed and read by the root `CMakeLists.txt`.
   - If generated by CubeMX, this should already exist and the only thing you need to do is fix the linker script line to be relative to the toolchain file itself instead (`${CMAKE_CURRENT_LIST_DIR}/../<name>.ld`).
2. **Linker script** `mcu/<name>/<...>.ld`, referenced by the toolchain file above.
   - The linker script's FLASH region must be the bootloader's size only (`BOOTLOADER_SIZE_PAGES * FLASH_PAGE_SIZE_BYTES`, e.g. 22K on the G431), so the build fails if the bootloader outgrows it instead of spilling into slot A.
3. **`mcu_interface` implementations**: `.c` files implementing every function in `boot_core/Inc/mcu_interface/`. The headers document each function, and `mcu/stm32g431cb/Core/Src/drivers/` is the reference implementation.
    - `peripherals.h`
        - `sr_peripherals_init()`: init HAL, clocks, GPIO, CAN, RNG, RTC etc. Called once before anything else.
        - `sr_peripherals_deinit()`: put everything back to reset state.
    - `can_driver.h`
        - `sr_fdcan_configure()`: only let `CFG_ISOTP_RX_ID` (`common_config/isotp_config.h`) into the RX FIFO and enable the RX interrupt.
        - `sr_fdcan_start()` / `sr_fdcan_stop()`: straightforward, start FD CAN and stop it.
        - `sr_fdcan_tx()` / `sr_fdcan_tx_blocking()`: queue a frame / queue it and wait until it's sent (or time out).
        - Not in the header, but the CAN RX interrupt must call `sr_isotp_can_isr_callback(data, length)` (`isotp/isotp.h`) for every received frame (see `isr.c` in the g431cb port).
    - `flash_driver.h`
        - `sr_flash_write()`: write one `FLASH_WRITE_GRANULARITY_BYTES` chunk.
        - `sr_flash_erase_page()`: erase pages in a bank.
        - `sr_flash_get_page_info()` / `sr_flash_get_page_address()`: convert between an address and a bank + page.
    - `sys_misc.h`
        - `jump_to_app()`: disable interrupts, stop SysTick, clear the NVIC, set `VTOR`, then load the app's MSP, **re-enable interrupts** and branch to its reset handler without touching the stack in between (see `branch_to()` in `sys_misc.c`).
        - `sr_counter_start()` / `sr_cyccnt()` / `sr_micros_since()`: cycle counter for ISO-TP timing.
        - `sr_millis()`, `sr_reset_mcu()`.
        - `sr_write_boot_magic()` / `sr_read_boot_magic()`: a value that survives a reset (backup register in the RTC domain is an option).
        - `sr_iwdg_start()`: start the independent watchdog, must reach `CFG_TEST_BOOT_IWDG_TIMEOUT_MS` (`common_config/boot_config.h`, 20 s).
    - `rng_driver.h`: `sr_rng_start()`, `sr_generate_number()` (hardware RNG, pseudo random fallback).
    - `led_blink.h`: `sr_led_init()`, `sr_led_blink()`.
4. **config/flash_config.h**, relative to your port's include path and named exactly. Use the G431's as the template. boot_core needs:
    - `FLASH_BEGIN_ADDRESS`: first address of flash, where the bootloader starts
    - `FLASH_PAGE_SIZE_BYTES`: smallest erasable unit (some vendors call it a sector)
    - `FLASH_WRITE_GRANULARITY_BYTES`: smallest programmable unit
    - `BOOTLOADER_SIZE_PAGES`: must match the linker script's FLASH length
    - `FW_SLOT_A_SIZE_PAGES`: at most 255, its last page holds the trailer
    - `FW_SLOT_B_SIZE_PAGES`: exactly `FW_SLOT_A_SIZE_PAGES + 1` (the extra page is the swap offset)

5. **Vector table alignment**: the app's vector table sits right after the `IMAGE_HEADER_SIZE` (1024 byte) image header. Check that 1024 meets your MCU's `VTOR` alignment (number of vectors * 4, rounded up to a power of 2), otherwise raise `IMAGE_HEADER_SIZE` in `boot_core/Inc/image_format.h`, `app_sdk/image_format.h` and `HEADER_PADDED_SIZE_BYTES` in `host_scripts/fmt_tool`. This likely shouldn't have to be done
6. **`mcu/<name>/CMakeLists.txt`** should:
    - target_sources your custom drivers into ${CMAKE_PROJECT_NAME}
        - Usually, stm32's autogenerated `cmake/stm32cubemx/CMakeLists.txt` should add all the autogenerated sources, so you just need to add the ones you create.
    - target_include_directories your include path. Make sure from this path `config/flash_config.h` is correct.
    - pull in any CubeMX-generated subdirectory (e.g. `add_subdirectory(cmake/stm32cubemx)`) and link its library

Use `mcu/stm32g431cb/` as the reference implementation for all of the above.

Finally, add an `ecus/<name>.cmake` pointing `ECU_MCU` at your new MCU (see Build Instructions).
