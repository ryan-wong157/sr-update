# SR-Update
My 5th year UNSW engineering undergraduate thesis project. A secure and fault-tolerant firmware update system for resource-constrained microcontrollers over CAN/CAN-FD.

## Design
This project is intended to support all of Sunswift Racing 8's electronic control units (ECUs) as a flash bootloader. It's purpose is to support the transfer of firmware binaries over the CAN/CAN-FD, ISO-TP and UDS protocols as well as enforce authenticity and integrity checks. It also features fault-tolerance inspired by MCUBoot which includes dual-slot flash layout for safe rollback.

### Features
1. ISO-TP over CAN/CAN-FD and UDS spec compatability including security_control implementation which requires an ED25519 private key to prove validity of the client. This includes using true RNG hardware (if supported) to generate a tester seed. 
2. Firmware integrity and authenticity checking via SHA256 hashes and ED25519 digital signatures (separate to the security_control one for extra security)
3. Dual-slot flash layout which enables safe rollback of new firmware
4. ECU Node ID baked into bootloader to confirm the right firmware is flashed 
5. Heartbeat mechanisms to detect against CAN/CAN-FD setting changes (TODO)
6. Core boot logic decoupled from MCU specific to allow easy porting (see below) and multi-target support
7. Pretty small, some 20KB flash size max (if compiled using Release preset) for the entire bootloader including crypto
8. A python script to package and sign application firmware binaries (not bootlaoder binaries) for flashing (TODO)
9. A temporary python client script to demonstrate the flashing

```
SR-Update
├── boot_core/                  MCU-agnostic bootloader logic
│   ├── Inc/
│   │   ├── mcu_interface/      Interface each MCU port must implement
│   │   ├── common_config/      
│   │   ├── uds/
│   │   └── isotp/
│   └── Src/                    boot_core sources
│
├── mcu/                        Directory container MCU ports
│   └── stm32g431cb/            stm32g431cb port
│       ├── Core/Src/drivers/   Implementation of boot_core/Inc/mcu_interface/*.h for this MCU
│       ├── Core/Inc/config/    MCU-specific config (flash geometry/layout etc.)
│       ├── cmake/              Toolchain file in here
│       └── CMakeLists.txt      This MCU's own sources/include dirs only (see Porting Instructions)
│
└── ecus/                       One .cmake file per ECU
    └── <name>.cmake            Which MCU it uses + its NODE_ID and Tx/Rx CAN IDs
```

## Build Instructions

Requires the `arm-none-eabi-gcc` toolchain and Ninja on `PATH`.

Configure and build a specific ECU with CMake presets:

```sh
cmake --preset Debug -DECU=example_ecu
cmake --build build/Debug # or Release
```

`-DECU=<name>` is required in the CMAKE configuration step and must match a file in `ecus/` (e.g for `ecus/example_ecu.cmake` do `-DECU=example_ecu`). The resulting binary is named `<ecu>_<mcu>_bl`, e.g `example_ecu_stm32g431cb_bl.elf`.

The ECU cmake file defines the target MCU and Node ID, ISO-TP CAN IDs

```cmake
# ecus/example_ecu.cmake
set(ECU_MCU stm32g431cb)

set(ECU_COMPILE_DEFS
    ECU_ID=0x10
    CFG_ISOTP_TX_ID=0x7A0
    CFG_ISOTP_RX_ID=0x7A8
)
```

Add a new ECU by adding a new `ecus/<name>.cmake` file in this shape.

## Porting Instructions

To add support for a new MCU, create `mcu/<name>/` and provide:

1. **Toolchain file** at `mcu/<name>/cmake/gcc-arm-none-eabi.cmake`. This path is fixed and read by the root `CMakeLists.txt`.
   - If generated by CubeMX, fix the linker script line to be relative to the toolchain file itself instead (`${CMAKE_CURRENT_LIST_DIR}/../<name>.ld`).
2. **Linker script** `mcu/<name>/<...>.ld`, referenced by the toolchain file above.
3. **`mcu_interface` implementations**. These are `.c` implementing every header in `boot_core/Inc/mcu_interface/`. See the headers for the implementation details
4. **config/flash_config.h**. This is relative to your mcu port include path, and must be named exactly. It outlintes flash geometry + slot layout macros for boot_core to use. See `boot_core/Inc/mcu_interface/flash_driver.h` and the stm32g4 flash_config.h for the exact macros you need to define
5. **`mcu/<name>/CMakeLists.txt`** should:
    - target_sources your custom drivers into ${CMAKE_PROJECT_NAME}
        - Usually, stm32's autogenerated `cmake/stm32cubemx/CMakeLists.txt` should add all the autogenerated sources, so you just need to add the ones you create.
    - target_include_directories your include path. Make sure from this path `config/flash_config.h` is correct.
    - pull in any CubeMX-generated subdirectory (e.g. `add_subdirectory(cmake/stm32cubemx)`) and link its library

Use `mcu/stm32g431cb/` as the reference implementation for all of the above.

Finally, add an `ecus/<name>.cmake` pointing `ECU_MCU` at your new MCU (see Build Instructions).
